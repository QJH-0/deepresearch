# OWASP Top 10 — 2021 安全风险报告

## 1. 报告概述

OWASP (Open Web Application Security Project) Top 10 是 Web 应用安全风险的权威参考标准。2021 版相较于 2017 版有重大调整，反映了当前 Web 安全威胁的新趋势。

## 2. OWASP Top 10 (2021)

### A01:2021 — 失效的访问控制 (Broken Access Control)

**风险等级**: 高

**描述**: 限制"谁"或"什么"可以访问资源未得到正确执行，允许攻击者查看或修改敏感数据或更改访问权限。

**常见场景**:
- 通过修改 URL 参数访问其他用户的账户数据
- 绕过 API 访问控制
- 未验证的权限提升
- 缺少服务端权限检查

**防御措施**:
- 实施默认拒绝 (deny by default) 策略
- 实施服务端权限验证
- 使用基于角色的访问控制 (RBAC)
- 记录所有访问控制失败事件

### A02:2021 — 加密失败 (Cryptographic Failures)

**风险等级**: 高

**描述**: 敏感数据（如密码、信用卡号、个人健康信息）未得到适当加密，导致数据泄露。

**关键要点**:
- 传输中数据必须使用 TLS 1.2+
- 存储中敏感数据必须加密
- 密码必须使用强哈希算法（bcrypt/scrypt/Argon2）
- 禁止使用弱加密算法（MD5, SHA1, DES）

### A03:2021 — 注入 (Injection)

**风险等级**: 高

**描述**: 攻击者通过恶意输入向应用程序注入代码，导致数据泄露或系统控制。

**类型**:
- SQL 注入
- NoSQL 注入
- OS 命令注入
- LDAP 注入
- XPath 注入

**防御**:
- 使用参数化查询
- 输入验证和白名单
- 使用 ORM 框架
- 最小权限原则配置数据库

### A04:2021 — 不安全设计 (Insecure Design)

**风险等级**: 中

**描述**: 2021 新增类别。强调架构层面的安全缺陷，而非实现层面的漏洞。

**关键概念**:
- 威胁建模 (Threat Modeling)
- 安全设计模式
- 安全开发生命周期 (SSDLC)
- 失败安全设计原则

### A05:2021 — 安全配置错误 (Security Misconfiguration)

**风险等级**: 中

**描述**: 应用或服务器配置不当，导致安全漏洞。

**常见问题**:
- 默认凭据未修改
- 错误信息泄露敏感信息
- 不必要的功能启用
- 安全头缺失 (CSP, HSTS, X-Frame-Options)
- 目录列表启用

### A06:2021 — 脆弱和过时的组件 (Vulnerable and Outdated Components)

**风险等级**: 中

**描述**: 使用已知有漏洞的第三方组件或过时版本的库。

**供应链安全**:
- SBOM (Software Bill of Materials) 管理
- 定期依赖扫描
- 组件版本锁定
- 安全补丁管理流程

### A07:2021 — 认证和会话管理失败 (Identification and Authentication Failures)

**风险等级**: 中

**描述**: 认证机制存在缺陷，允许攻击者冒充合法用户。

**防御要点**:
- 多因素认证 (MFA)
- 强密码策略
- 会话超时管理
- 防暴力破解（速率限制、CAPTCHA）
- 安全的密码重置流程

### A08:2021 — 软件和数据完整性失败 (Software and Data Integrity Failures)

**风险等级**: 中

**描述**: 2021 新增类别。涉及软件更新、CI/CD 管道和数据完整性的安全验证。

**关键场景**:
- 未验证的软件更新
- 不安全的 CI/CD 管道
- 反序列化漏洞
- 不安全的依赖管理

### A09:2021 — 安全日志和监控失败 (Security Logging and Monitoring Failures)

**风险等级**: 低

**描述**: 安全事件未被记录或监控，导致无法及时检测和响应攻击。

**关键要求**:
- 记录所有认证、授权和访问事件
- 日志格式标准化（JSON/CEF）
- 实时告警机制
- 日志防篡改保护
- 定期安全审计

### A10:2021 — 服务端请求伪造 (SSRF)

**风险等级**: 低

**描述**: 2021 新增类别。应用在处理用户提供的 URL 时未验证目标地址，导致 SSRF 攻击。

**影响**:
- 访问内部网络服务
- 读取云元数据 API
- 端口扫描内网
- 绕过防火墙

## 3. 2021 vs 2017 变化对比

| 排名 | 2021 | 2017 | 变化 |
|------|------|------|------|
| A01 | 失效的访问控制 | 注入 | 从 #5 升至 #1 |
| A02 | 加密失败 | 失效的认证 | 重命名 |
| A03 | 注入 | 敏感数据泄露 | 从 #1 降至 #3 |
| A04 | 不安全设计 (新增) | XML 外部实体 (XXE) | 全新类别 |
| A05 | 安全配置错误 | 失效的访问控制 | 从 #6 升至 #5 |
| A06 | 脆弱组件 | 安全配置错误 | 从 #9 升至 #6 |
| A07 | 认证失败 | 跨站脚本 (XSS) | 合并 |
| A08 | 完整性失败 (新增) | 不安全的反序列化 | 全新类别 |
| A09 | 日志监控失败 | 使用含已知漏洞的组件 | 从 #10 升至 #9 |
| A10 | SSRF (新增) | 不足的日志和监控 | 全新类别 |

## 4. 总结

OWASP Top 10 2021 的核心变化在于：

1. **访问控制超越注入成为 #1 风险** — 反映了访问控制问题的普遍性和严重性
2. **新增三个类别** — 不安全设计、完整性失败、SSRF，体现了安全威胁的演进
3. **强调架构和流程安全** — 不再仅关注代码层面漏洞
4. **供应链安全重要性上升** — 组件和依赖管理成为关键防线
