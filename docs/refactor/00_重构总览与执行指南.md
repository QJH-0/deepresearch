## 4. 环境准备（首次执行前完成一次）

1. **中间件**：`docker compose -f docker-compose.middleware.yml up -d`
   （服务：postgres:5432、redis:6379、milvus:19530、minio:9900、rabbitmq:5672/15672、etcd）
2. **环境变量**：参考 `.env.example` 配置 `.env`，关键项：`DASHSCOPE_API_KEY`、`POSTGRES_DSN`、`REDIS_URL`、`RABBITMQ_URL`、`MILVUS_HOST/PORT`、`MINIO_*`
3. **后端依赖**：`pip install -r requirements.txt`
4. **前端依赖**：`cd agent_front && npm install`
5. **后端启动**：`uvicorn app.app_main:app --port 8000`（工作目录为项目根）
6. **前端启动**：`cd agent_front && npm run dev`（代理 /api → 127.0.0.1:8000）

| 场景 | 命令（项目根目录执行） |

**测试基础设施说明**：`app/test/conftest.py` 提供 `_WildcardMockFinder` 通配 mock（dashscope/pymilvus/redis/pika 等未安装时自动挂空模块）。新增测试若 import 真实第三方包，遵循现有模式：用 `unittest.mock` / `monkeypatch` 打桩，不依赖真实中间件即可运行。

## 6. 执行模型规约（每个任务开始前重读本节）

1. **先读后改**：每个任务文档的「现状分析」列出了目标文件。动手前必须完整阅读这些文件，以代码实际内容为准；文档描述与代码冲突时，以代码为准并在执行日志中记录差异。
2. **按步骤执行**：严格按任务文档「实施步骤」顺序执行，每步完成后立即执行该步附带的「验证」命令；验证失败不得进入下一步。
3. **测试同步**：每个任务完成后，必须按对应阶段 `TEST_阶段X测试用例.md` 编写并跑通该任务关联的测试用例，然后跑后端全量回归确认无破坏。
4. **最小变更**：只改任务文档「涉及文件」清单内的文件；发现范围外问题只记录风险，不顺手修复。
5. **提交规范**：每完成一个 R 任务且测试通过后，独立提交一次，格式：`refactor(R任务号): 任务标题`，例：`refactor(R1.1): Web 搜索 Provider 链式降级`。
6. **停止条件**：遇到以下情况立即停止当前任务并报告，不得自行发挥：
   - 文档设计基于的代码结构已发生重大变化，实施步骤无法对应；
   - 需要执行任务文档标注「需用户确认」的破坏性操作（DDL、删除数据、依赖降级等）；
   - 全量回归出现与本次改动无关的新失败。
7. **日志要求**：每个任务在 `docs/refactor/执行日志.md`（自行创建并累积）追加一节：任务号、完成日期、修改文件清单、验证命令与结果、遗留问题。

## 7. 通用设计约定（全任务生效）

- **配置新增**：业务可调参数一律进 `config.json` + `app/backend/config/settings.py` 的 `BusinessSettings`，不硬编码；中间件连接参数进 `.env` 的 `MiddlewareSettings`。
- **事件协议**：SSE 事件类型固定 10 种（见 `app/backend/schemas/events.py` 的 `EVENT_REGISTRY`），禁止新增/删除事件类型；新增字段须为可选字段，并同步更新 `docs/event-protocol.json`。
- **降级模式**：所有外部依赖（搜索 API、rerank、PG、MQ、Redis）必须实现「主路径失败 → 静默降级 → 记 warning 日志 → 不阻塞主流程」的兜底链，与项目现有风格一致。
- **异步规范**：FastAPI 路由与 service 层全 async；阻塞调用（requests/urllib/文件 IO）用 `asyncio.to_thread` 包装（参考 `tools.py` 中 DuckDuckGoProvider 写法）。
- **日志规范**：统一走 `logging.getLogger(__name__)`，禁止再新增 `setup_logging` 类 root logger 挂载（阶段四 R4.1 会统一收口）。
- **注释规范**：只写「为什么」，不写「做什么」；删除被替代的旧实现，不留注释封存的死代码。
- **中文 LLM Prompt**：新增 prompt 与现有一致使用中文（参考 `rag/core.py` 的 REWRITE_PROMPT / RERANK_PROMPT 写法）。

| 门禁项 | 标准 |

| 回归 | `python -m pytest app/test -q` 全绿（或与阶段开始前基线一致，新增失败为 0） |

| 自动化冒烟 | 涉及流式/检索的阶段：通过 Playwright 脚本自动完成完整研究任务（提问 → 中断 → 恢复 → 报告）无报错 |
| 文档同步 | 改动涉及事件协议/接口时同步更新 `docs/event-protocol.json` 与受影响的 docs 文档 |

## 9. 风险与注意事项

- **DDL 变更**：R1.2（PG 全文检索索引）、R3.1（DLQ 队列声明）涉及数据库/中间件结构变更，相关 DDL 草案已在任务文档中给出并标注「需用户确认后执行」，执行模型不得跳过确认直接变更。
- **LLM 调用成本**：R1.3/R1.4/R2.3 新增 DashScope 调用，务必实现降级路径（失败回退旧逻辑），保证 API Key 无效或欠费时系统仍可用。
- **qwen 模型能力**：`enable_thinking` 仅 qwen3 系列/qwen-plus 支持，配置必须可开关（默认关闭或按节点开关），避免不支持的模型报错。
- **E2E 环境**：E3–E5 修复验证需要 `docker compose -f docker-compose.app.yml up` 完整栈；本机无 Docker 时标注「待实机回归」并记录受限原因。
