# R4.4 消息双轨制改造：用户对话与 Agent 内部上下文分离

> 阶段四 · 缺陷修复与收口 | 对应问题：对话历史中混入 agent 内部推理 prompt（如"用户问题：xxx 规则引擎初判：direct"），被前端当作用户消息展示

## 1. 问题根因

`state["messages"]` 同时承担三个职责，导致内部推理 prompt 污染前端对话历史：

| 职责 | 写入方 | 读取方 | 问题 |
|------|--------|--------|------|
| LLM 上下文 | 各节点构造 `HumanMessage(内部prompt)` + LLM 返回 | 下一节点 agent.invoke/astream | prompt 含内部推理内容 |
| 前端对话历史 | 同上 | `get_thread_messages` 从 checkpoint 读取 | **内部 prompt 被当用户消息展示** |
| 摘要压缩输入 | 同上 | `summary_service` 从 checkpoint 读取 | 内部 prompt 被压缩进摘要 |

### 污染路径（改造前）

```
intent_node: return {"messages": [HumanMessage("用户问题：xxx\n规则引擎初判：direct\n请输出JSON..."), AIMessage(...)]}
plan_node:   return {"messages": [HumanMessage("用户需求：xxx\n请先做大纲..."), AIMessage(...)]}
web_search:  return {"messages": [HumanMessage("请基于以下网页证据整理JSON..."), AIMessage(...)]}
...
    ↓ add_messages reducer 累加到 state["messages"]
    ↓ checkpoint 持久化
get_thread_messages() 读取 state["messages"]
    ↓ 按 type=human → role:"user" 映射
前端显示 → 用户看到 "用户问题：xxx 规则引擎初判：direct..." 作为自己的消息
```

## 2. 改造目标

将 `state["messages"]` 拆分为两个独立字段：

| 字段 | 用途 | reducer | 写入方 | 读取方 |
|------|------|---------|--------|--------|
| `chat_messages` | 用户可见对话：用户真实提问 + AI 最终回复 | `add_messages` | 入口层写用户提问；`run.completed` 时写 AI 回复 | `get_thread_messages` → 前端；`summary_service` |
| `agent_messages` | agent 内部上下文：各节点 LLM prompt + response | `add_messages` | 各节点 `_invoke_json_agent` / `astream` | 下一节点 agent（如需上下文） |

### 改造后数据流

```
用户输入 "你好"
    ↓
stream_research 入口
    ↓ chat_messages = [HumanMessage("你好")]   ← 用户真实输入
    ↓ agent_messages = []                       ← 初始为空
    ↓
intent_node → agent_messages += [HumanMessage(内部prompt), AIMessage(llm返回)]
plan_node   → agent_messages += [HumanMessage(内部prompt), AIMessage(llm返回)]
...
write_node  → agent_messages += [HumanMessage(内部prompt)]
    ↓
run.completed
    ↓ chat_messages += [AIMessage(最终报告)]    ← AI 回复
    ↓
get_thread_messages() 读取 chat_messages
    → 前端只看到 [用户:"你好", AI:"# 研究报告..."]
```

## 4. 详细设计

### 4.1 State 改造 (`state.py`)

```python
class ConversationState(TypedDict):
    chat_messages: Annotated[list, add_messages]       # 用户可见对话
    agent_messages: Annotated[list, add_messages]       # agent 内部上下文
    clarifications: Annotated[list, operator.add]
    conversation_summary: str
```

`create_initial_state` 中：
- `chat_messages`: 入口层注入用户提问，初始为 `[]`（由 `stream_research` 写入）
- `agent_messages`: 初始为 `[]`

### 4.2 节点改造

所有节点 return 中的 `"messages": messages` 统一改为 `"agent_messages": messages`。

`_invoke_json_agent` 本身不改 — 它返回 `(payload, content, messages)` 三元组，调用方决定写到哪个字段。

### 4.3 入口层改造 (`research_service.py`)

**`stream_research`**: 构建初始 state 时写入 `chat_messages`
```python
input_state["chat_messages"] = [HumanMessage(content=query)]
input_state["agent_messages"] = []
```

**`run.completed`**: 最终报告写入 `chat_messages`
```python
await self._app.aupdate_state(config, {
    "chat_messages": [AIMessage(content=final)]
})
```

**`get_thread_messages`**: 读 `chat_messages`，兼容旧 checkpoint
```python
chat_msgs = snapshot.values.get("chat_messages")
if chat_msgs is None:
    # 旧 checkpoint 兼容：从 query + final 恢复
    ...
```

**`_apply_summary_if_needed`**: 从 `chat_messages` 读取

### 4.4 摘要改造 (`summary_service.py`)

`summarize_if_needed` 接收的 `messages` 参数改为 `chat_messages`，不再包含内部推理 prompt。

### 4.5 兼容旧 checkpoint

- `get_thread_messages`: 优先读 `chat_messages`，不存在时降级从 `query` + `final` 恢复
- `_apply_summary_if_needed`: 优先读 `chat_messages`，不存在时降级读旧 `messages`
