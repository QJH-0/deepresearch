  - `app/backend/infra/postgres_client.py` — `ChunkRepository` 新增 `get_chunk_status()` 方法

  - `python -m pytest app/test/test_chunk_dlq.py -q` → 10 passed ✅
- **技术决策**：
  - 重试计数 key 用 `md5(body)` 而非 delivery_tag（requeue 后 tag 递增不复用）
  - 失败后 `time.sleep(min(count*2, 10))` 退避再 nack(requeue=True)，防止无限快速循环
  - 幂等闸门在 `_process_message` 开头：`repo.get_chunk_status(chunk_id) == "indexed"` 直接返回
  - 状态回写失败 → 抛异常走重试路径，保证「成功状态 ⇒ 已向量化」不变式
  - DLQ 与 outbox 补偿不冲突：补偿扫 PG pending 记录，DLQ 重放扫 RabbitMQ 死信队列

  - ⚠️ 旧 `chunk-sync.queue` 需删除后以新参数（带 DLX）重新声明——RabbitMQ 不允许原地修改队列参数
  - 未确认前不会实际执行队列重建；outbox 表是事实源，消息可由补偿重建
- **遗留问题**：

## R4.2 E3-E5 前端缺陷修复与 E2E 固化

- **完成日期**：2026-09-06
- **根因分析**：
  - **E3 无回复气泡**：`run.started` 事件创建了一条空 assistant 消息（无 message_id），后续 `message.start` 携带不同 message_id 创建了第二条消息。`message.delta` 追加到第二条，第一条空消息残留导致 UI 渲染异常
  - **E4 Vue recursive updates**：与 E3 关联——空消息对象在响应式系统中被触发多次更新。`run.started` 不再创建消息后循环消除
  - **E5 取消阻塞**：依赖 E4 运行态，E4 修复后取消流程正常
- **修改文件清单**：
  - `agent_front/src/composables/useEventStream.ts` — E3 修复：`run.started` 不再创建空 assistant 消息，改为 `chat.setRunning(threadId)` 只设置 running 状态；`message.delta` 增加容错——delta 先于 message.start 到达时惰性初始化消息对象
  - `agent_front/src/stores/chat.ts` — 新增 `setRunning(threadId)` 方法（只设置 `t.running = true`，不创建消息）
  - `agent_front/test/test_chat_render.test.ts` — 新增 T4.2-01~07 测试用例（7 tests）
- **验证命令与结果**：
  - `npx vitest run test_chat_render.test.ts` → 7 passed ✅
  - `npx vitest run` → 40 passed ✅（前端全量）
  - `python -m pytest app/test -q` → 424 passed, 6 failed（基线），4 skipped ✅
- **技术决策**：
  - E3 根因：`run.started` 创建空消息 → `message.start` 再创建 → 两条消息中一条空残留。修复：消息创建统一由 `message.start` 驱动；`run.started` 只设置 running 状态
  - `message.delta` 容错：如果 `message.start` 丢失或时序乱，delta 到达时检查消息是否存在，不存在则创建——保证不丢 token
  - E4/E5 不需要独立修复——根因是 E3 的空消息触发响应式异常
