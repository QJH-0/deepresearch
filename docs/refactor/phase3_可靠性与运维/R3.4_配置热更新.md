# R3.4 配置热更新

> 阶段三 · 可靠性与运维 | 对应落地修复清单 #10：实现管理端点：config.json 修改 → 校验 → 原子生效（或修正口径为重启生效）
> 前置阅读：`docs/refactor/00_重构总览与执行指南.md`

## 1. 目标

实现 **config.json 热更新管理端点**：管理员修改磁盘上的 `config.json` 后，调用 `POST /api/v1/admin/config/reload` 使新配置**校验通过后原子生效**，无需重启服务；校验失败返回 422 并保持旧配置不变。同时明确**热更新生效边界**（哪些配置项热更后立即生效、哪些需要重启），避免「以为生效了实际没有」的口径问题。

**验收标准**：

- [ ] `POST /api/v1/admin/config/reload`：读取磁盘 config.json → Pydantic 校验 → 校验通过原子替换内存配置；校验失败返回 422（含字段级错误信息），内存配置保持不变
- [ ] `GET /api/v1/admin/config`：返回当前生效的业务配置（脱敏——不含任何 API Key / DSN / 密码）
- [ ] 热更新生效范围文档化（见 3.4 生效边界表），并在响应中标注哪些项需重启
- [ ] 配置读取路径统一：业务代码读 BusinessSettings 的地方在 reload 后能取到新值（惰性单例重建或直读）
- [ ] reload 有并发安全保证（reload 进行中读配置不会拿到半新半旧）
- [ ] 单元测试全部通过，全量回归无破坏

## 2. 现状分析（动手前先完整阅读以下文件）

| 文件 | 现状要点 |
| --- | --- |
| `app/backend/config/settings.py` | 三层配置：`MiddlewareSettings`（.env）、`BusinessSettings`（config.json，`_load_from_json()` 手动加载兼容 pydantic-settings<2.4）、`AppSettings`（lazy property 组合）。**配置在进程启动时加载一次，无任何 reload 机制** |
| `config.json` | 业务配置：model / max_iterations / enable_memory / hitl_enabled / hitl_config / summary_* / checkpointer_backend 等（阶段一二三新增字段也在其中） |
| `app/mult_agents/config.py` | `AppConfig` 兼容层（dataclass），`from_file()` 从 .env+config.json 构建；`ResearchService._build_runtime_config()` 每次请求从 AppConfig 派生运行时配置 |
| `app/backend/router/health_router.py` | 现有路由组织范本；无 admin 路由 |
| `app/app_main.py` | FastAPI 实例与路由注册方式 |

**现状问题**：改 `config.json` 必须重启；`ResearchService` 等长生命周期单例在初始化时缓存的配置（如 AgentBundle 的模型、checkpointer）不会随文件变化更新——「热更新」若不划清边界会产生配置假象。

## 3. 详细设计

### 3.1 配置访问统一化（前置重构，小步）

现状 `BusinessSettings` 通过 `AppSettings` lazy property 暴露。设计：

- `settings.py` 增加模块级 `get_business_settings() -> BusinessSettings` 单例 getter 与 `_set_business_settings(new)` 替换器（线程安全：模块级变量整体替换——Python 引用赋值原子，读方要么全旧要么全新）
- 全局 grep `BusinessSettings` / `business` 配置的消费点（`ResearchService._build_runtime_config`、`AppConfig.from_file` 等）：读取处改为调 `get_business_settings()`（**每次请求时取**，而不是构造时缓存到实例属性）
- 执行时先 grep 确认全部消费点数量与形态；消费点若超过 ~10 处且分散，可在执行日志记录后只改「运行时可变」的关键点（max_iterations / hitl / memory 开关等），结构性配置留重启

### 3.2 reload 端点（新增 `app/backend/router/admin_router.py`）

```python
router = APIRouter(prefix="/api/v1/admin", tags=["admin"])

@router.get("/config")
async def get_config():
    """当前生效业务配置（脱敏视图）。"""
    biz = get_business_settings()
    return biz.model_dump()      # BusinessSettings 全部为业务字段，无密钥；
                                 # 执行时逐字段确认无敏感项后输出，有疑义字段加进排除列表

@router.post("/config/reload")
async def reload_config():
    """重读磁盘 config.json 并原子生效。校验失败 422。"""
    config_path = _resolve_config_path()             # 与 ResearchService 同源的 CONFIG_PATH 逻辑
    try:
        raw = json.loads(Path(config_path).read_text(encoding="utf-8"))
        new_biz = BusinessSettings(**{k: v for k, v in raw.items() if k in _BUSINESS_FIELDS})
    except ValidationError as e:
        raise HTTPException(422, detail={"message": "config.json 校验失败", "errors": e.errors()})
    except Exception as e:
        raise HTTPException(422, detail={"message": f"config.json 解析失败: {e}"})

    old = get_business_settings()
    _set_business_settings(new_biz)                   # 原子替换
    restart_required = _diff_restart_required(old, new_biz)
    return {
        "reloaded": True,
        "restart_required_fields": restart_required,   # 变化且需重启的字段列表
        "applied_fields": [k for k in new_biz.model_fields if getattr(old, k, None) != getattr(new_biz, k, None)],
    }
```

路由注册进 `app_main.py`。

### 3.3 鉴权（最小实现）

admin 端点不裸奔：`.env` 增加 `ADMIN_TOKEN`（可空）；非空时请求头 `X-Admin-Token` 必须匹配，否则 401；为空时放行（本地开发场景）。`MiddlewareSettings` 增加 `admin_token: str = ""`。

### 3.4 生效边界表（文档化 + `_diff_restart_required` 实现依据）

| 配置项 | 热更生效 | 说明 |
| --- | --- | --- |
| `max_iterations` | ✅ | 每次请求经 `_build_runtime_config` 派生 |
| `hitl_enabled` / `hitl_config` | ✅ | 同上（新会话生效） |
| `enable_memory` / `memory_*` | ✅ | 同上 |
| `summary_*` | ✅ | summary_service 每次触发时读取（执行时确认其取值时机） |
| `search_providers` | ✅ | R1.1 链为惰性单例——reload 后需失效缓存：`_set_business_settings` 内顺带重置 `tools._PROVIDER_CHAIN = None`（通过注册回调实现，见 3.5） |
| `rerank_model` / `enable_rerank_model` | ✅ | RAGSystem 若为惰性构建则新会话生效；确认构建时机 |
| `evidence_llm_fusion` / `evidence_prior_weight` | ✅ | 每次评分时读取 |
| `sse_heartbeat_seconds` | ✅ | 每条流开始时读取 |
| `thinking_nodes` | ❌ 需重启 | AgentBundle 构建时固化 |
| `model`（主力模型） | ❌ 需重启 | AgentBundle 构建时固化 |
| `checkpointer_backend` | ❌ 需重启 | 服务启动时固化 |

`_diff_restart_required(old, new)`：对表中「需重启」字段做变更比对，返回发生变化的字段名列表。

### 3.5 reload 副作用回调

```python
# settings.py 中
_RELOAD_CALLBACKS: list[Callable] = []

def register_reload_callback(fn: Callable) -> None:
    """配置热更后的失效回调（如重置搜索链单例）。"""
    _RELOAD_CALLBACKS.append(fn)

def _set_business_settings(new: BusinessSettings) -> None:
    global _BUSINESS
    _BUSINESS = new
    for fn in _RELOAD_CALLBACKS:
        try:
            fn()
        except Exception as exc:
            logger.warning("[settings] reload 回调失败 | %s | %s", getattr(fn, "__name__", fn), exc)
```

R1.1 的 `tools.py` 在模块加载时 `register_reload_callback(lambda: setattr(sys.modules[__name__], "_PROVIDER_CHAIN", None))`（或等价的失效函数）。

## 6. 风险与回滚

- **风险 1**：配置生效口径不清导致「改了没生效」的排障成本。缓解：3.4 边界表 + reload 响应显式返回 restart_required_fields。
- **风险 2**：坏配置热载导致运行中请求异常。缓解：Pydantic 校验前置（422 拒载），字段默认值兜底。
- **风险 3**：admin 端点越权。缓解：ADMIN_TOKEN 鉴权；脱敏 GET 视图。
- **回滚**：reload 端点纯增量功能，不调用即无影响；revert 单 commit。
