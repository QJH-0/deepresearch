# R1.2 PostgreSQL 关键词检索与 RRF 融合

> 阶段一 · 检索链路 | 对应落地修复清单 #2：PG 关键词 + RRF 融合
> 前置阅读：`docs/refactor/00_重构总览与执行指南.md`；依赖 R1.1 已完成（无代码依赖，仅执行顺序约定）

## 1. 目标

将本地知识库关键词检索从**进程内存 BM25**（重启即失效、单实例无法共享）升级为 **PostgreSQL 全文检索**，并与 Milvus 稠密向量召回做 **RRF（倒数排名融合）**，替换当前「内容 hash 拼接去重」的合并方式。BM25 保留为 PG 不可用时的进程内降级。

**验收标准**：

- [ ] `PostgresKeywordRetriever` 基于 `document_chunks` 表实现关键词检索（tsvector 全文匹配），返回带排名的文档列表
- [ ] `rrf_fuse()` 纯函数实现：多路召回列表融合，只依赖排名不依赖分数
- [ ] `RAGSystem.search_records()` 检索主链路改为：Milvus 多变体召回 + PG 关键词召回 → RRF 融合 → rerank → Parent-Child 扩展
- [ ] PG 不可用时自动降级 BM25，主流程不报错
- [ ] ⚠️ DDL（tsvector 生成列与索引）经用户确认后执行
- [ ] 单元测试全部通过，全量回归无破坏

## 2. 现状分析（动手前先完整阅读以下文件）

| 文件 | 现状要点 |
| --- | --- |
| `app/mult_agents/rag/core.py` | `RAGSystem`：`search_records()` 流程为「QueryRewriter 多变体 → 每个变体 Milvus `similarity_search(k=recall_k)` → BM25 `search(k=recall_k)` → content hash 去重合并 → LLMReranker（候选 > k*2 时触发）→ Parent-Child 扩展 → Top-K」。`RAGConfig` 已有 `enable_fulltext: bool = True` 与 `postgres_dsn: str = ""` 字段但**未接线** |

## 3. 详细设计

### 3.1 RRF 融合算法（纯函数，模块级新增）

```python
def rrf_fuse(
    result_lists: list[list],
    k: int = 60,
    top_k: int | None = None,
) -> list:
    """Reciprocal Rank Fusion：多路召回列表融合。

    score(doc) = Σ_i 1 / (k + rank_i(doc))，rank 从 1 开始。
    只依赖各路的排名顺序，不依赖分数分布，对异构打分天然鲁棒。
    doc 的同一性由 doc_key 决定（调用方传入 key 提取或用默认 content hash）。
    """
    scores: dict[str, float] = {}
    doc_map: dict[str, object] = {}
    for result_list in result_lists:
        for rank, doc in enumerate(result_list, start=1):
            key = doc_key(doc)          # 默认: md5(page_content)
            if key not in doc_map:
                doc_map[key] = doc
            scores[key] = scores.get(key, 0.0) + 1.0 / (k + rank)
    ranked = sorted(scores.items(), key=lambda kv: kv[1], reverse=True)
    fused = [doc_map[key] for key, _ in ranked]
    return fused[:top_k] if top_k else fused
```

### 3.2 PostgresKeywordRetriever（新增类）

```python
class PostgresKeywordRetriever:
    """基于 document_chunks 表的 PG 全文关键词检索（专有名词/型号/编码字面匹配）。"""

    def __init__(self, dsn: str, top_k: int = 20):
        self._dsn = dsn
        self._top_k = top_k

    @property
    def available(self) -> bool:
        return bool(self._dsn)

    def search(self, query: str, k: int | None = None) -> list:
        """返回 langchain Document 列表（metadata 与 Milvus 召回保持同构）。"""
        # SQL（同步 psycopg2，调用方用 asyncio.to_thread 包装）：
        #   SELECT chunk_id, content, doc_id, parent_id, section_path
        #   FROM document_chunks
        #   WHERE content_tsv @@ plainto_tsquery('simple', %(query)s)
        #     AND status = 'indexed'
        #   ORDER BY ts_rank(content_tsv, plainto_tsquery('simple', %(query)s)) DESC
        #   LIMIT %(k)s
        # 返回的 Document.metadata 携带 parent_id/doc_id/section_path/chunk_id，
        # 与 Milvus 子块 metadata 同构，保证 Parent-Child 扩展逻辑复用。
```

实现细节：

- 连接管理：每次 `search` 用短连接（`psycopg2.connect(self._dsn)`），或在 `RAGSystem` 层维护一个连接（与 `ChunkRepository` 复用连接方式保持一致——先读 `postgres_client.py` 现有连接管理模式再定）
- 中文分词：PG 内置无中文分词，`'simple'` 配置按空白切词，中文长 query 会整体作为一个 lexeme。**接受该局限**（关键词路本就面向型号/编码/英文专名）；若需增强，后续可换 `zhparser` 扩展，本期不做
- 异常处理：连接失败/查询异常 → 记 warning 日志，返回 `[]`，由上层降级 BM25

### 3.3 DDL 草案（⚠️ 需用户确认后执行，执行模型不得自行变更）

```sql
-- 在 document_chunks 表增加全文检索生成列与 GIN 索引
ALTER TABLE document_chunks
    ADD COLUMN IF NOT EXISTS content_tsv tsvector
    GENERATED ALWAYS AS (to_tsvector('simple', coalesce(content, ''))) STORED;

CREATE INDEX IF NOT EXISTS idx_chunks_content_tsv
    ON document_chunks USING GIN (content_tsv);
```

- 影响评估：`document_chunks` 当前数据量级为个人项目规模（千级 chunk），`GENERATED ALWAYS ... STORED` 列 + GIN 索引回填在秒级完成；对插入路径有轻微写放大，可接受
- 若 `document_chunks.content` 列名与实际不符（以 `postgres_client.py` 的 DDL 为准），按实际列名调整
- 回滚：`DROP INDEX IF EXISTS idx_chunks_content_tsv; ALTER TABLE document_chunks DROP COLUMN IF EXISTS content_tsv;`

### 3.4 RAGSystem 检索主链路改造（`search_records()`）

改造前后对比：

```
改造前：多变体向量召回 + BM25 → content hash 去重 → rerank → parent 扩展
改造后：多变体向量召回 + PG 关键词召回 → rrf_fuse 融合 → rerank → parent 扩展
```

伪代码：

```python
# 1. 向量路（保持现状：多变体 Milvus 召回）
vector_docs: list[Document] = []
for q in query_variants:
    vector_docs.extend(self.vectorstore.similarity_search(q, k=self.config.recall_k))

# 2. 关键词路（新：优先 PG，降级 BM25）
keyword_docs: list[Document] = []
if self._keyword_retriever is not None and self._keyword_retriever.available:
    try:
        keyword_docs = await asyncio.to_thread(
            self._keyword_retriever.search, query, k=self.config.recall_k
        )
    except Exception as exc:
        logger.warning("[rag] PG 关键词检索失败，降级 BM25 | %s", exc)
if not keyword_docs and self.config.enable_bm25 and self.bm25._documents:
    keyword_docs = [doc for doc, _ in self.bm25.search(query, k=self.config.recall_k)]

# 3. RRF 融合替代 hash 去重
merged_docs = rrf_fuse([vector_docs, keyword_docs])

# 4. rerank 与 parent 扩展逻辑保持现状（enable_reranker / enable_parent_child 分支不变）
```

- `_keyword_retriever` 在 `RAGSystem.__init__` 中按 `self.config.postgres_dsn` 与 `enable_fulltext` 条件创建
- `RAGConfig` 新增字段：`rrf_k: int = 60`（RRF 平滑常数）
- content hash 去重逻辑删除（`seen_hashes` 相关），由 RRF 的 doc_key 天然合并同文档；RRF 内部 key 默认用 `md5(page_content)`

### 3.5 配置接线

`RAGConfig.postgres_dsn` 当前默认空字符串。改造后初始化路径（`RAGSystem` 的构造调用方，先 grep `RAGSystem(` 确认全部调用点）统一从 `settings.py` 的 `MiddlewareSettings.postgres_dsn`（.env `POSTGRES_DSN`）取值注入，保证「文档管道写 PG」与「检索读 PG」指向同一库。

## 6. 风险与回滚

- **风险 1**：入库链路若未将 chunk 全量写入 `document_chunks`（文档管道异步链路中 chunk 可能仅在向量化成功后才回写状态），PG 关键词路会漏检。缓解：执行前核查 `insert_document_with_chunks` 的写入时机与 `status='indexed'` 过滤条件，必要时过滤条件放宽为 `status IN ('pending','indexed')`，记录决策到执行日志。
- **风险 2**：`simple` 分词对纯中文 query 召回弱。已声明为已知局限，不影响验收。
- **回滚**：代码单 commit 可 revert；DDL 回滚语句见 3.3；`enable_fulltext=False` 配置项可整体关闭 PG 检索路回退 BM25。
