# DeepResearch 功能需求文档

> 多智能体深度研报系统 · 产品与技术需求基线
> 本文档是系统实现的唯一需求依据，包含功能模块、核心功能点、用户交互流程与非功能需求。

---

## 1. 产品定位

DeepResearch 是一个多智能体深度研报系统。用户提出研究问题后，系统经澄清与计划确认，由编排器动态调度多个并行研究智能体完成多源检索与证据核验，最终一次性产出**句级引用、事实支持率经过校验**的结构化研究报告。全程流式可观察、可中断、可转向、可恢复。

**产品目标**：

- 研究报告的每一句关键论述都可追溯到具体来源，且来源内容经事实支持率校验
- 简单问题秒级直答，复杂问题深度研究，资源消耗随问题复杂度自适应
- 长时间研究的全程可观测、可介入、可恢复

## 2. 用户角色

| 角色 | 能力 |
| --- | --- |
| 普通用户 | 发起研究、流式观察、HITL 介入、中断/转向/恢复、会话管理、知识库管理、报告导出、查看个人记忆 |
| 管理员 | 普通用户全部能力 + 运行时配置查看与热更新、系统观测 |

## 3. 系统架构概述

### 3.1 三阶段混合编排

```
┌─ Scope ─────────────┐ ┌─ Research（动态委派）───────────────────┐ ┌─ Write ─────────────┐
│ 意图路由             │ │ supervisor 编排器                      │ │ writer 一次性成文     │
│   ├ 简单问题→直答    │ │   ├ 拆分子主题                         │ │   ↓                  │
│   └ 复杂问题→澄清    │ │   ├ 并行派发 N 个 researcher 子智能体  │ │ CitationAgent        │
│ 澄清对话（≤2 轮）    │ │   │   （独立上下文，ReAct + 工具循环）  │ │   句级事实支持率校验   │
│   ↓ 压缩             │ │   ├ 汇总回传、判断知识缺口              │ │   ↓                  │
│ research brief       │ │   └ 缺口未闭合且预算未尽 → 再派/收口   │ │ 质量门禁 → 导出       │
│   ↓ HITL 计划批准    │ │                                        │ │                      │
└──────────────────────┘ └────────────────────────────────────────┘ └──────────────────────┘
```

### 3.2 架构规则

1. **阶段边界静态，研究内部动态**：Scope/Research/Write 三段为固定骨架；Research 内部由 supervisor 在运行时决定子主题拆分、并行度与补充轮次。
2. **子智能体独立上下文**：每个 researcher 在独立上下文窗口内执行 tool-calling ReAct 循环，结束前做一次清洗压缩，只回传结论、证据与来源清单——工具返回的大体量内容不进入 supervisor 上下文。
3. **并行只用于检索与阅读，写作不并行**：研究收口后由单一 writer 一次性成文，保证叙述连贯。
4. **委派简报四要素**：supervisor 派发子智能体必须给出明确目标、边界、输出格式、来源指引。
5. **预算硬上限**：总研究轮次、并行子智能体数（默认 3–5）、单子智能体工具调用次数、证据条数与字符预算均可配上限——同时作为成本控制与质量控制（工具调用过多会降低事实准确率）。
6. **上下文工程**：对话压缩为 research brief 作为全程基准；超大产出落对象存储，上下文内只传引用指针。
7. **检查点持久化**：阶段边界与 supervisor 决策点落 PostgreSQL 检查点，支撑中断恢复、HITL 挂起与历史回溯。

### 3.3 智能体角色

| 角色 | 职责 |
| --- | --- |
| intent_router | 意图分类：直接回答 / 澄清 / 深度研究 |
| direct_responder | 简单问答直答（秒级） |
| clarifier | 澄清问题生成（≤2 轮） |
| supervisor | 子主题拆分、并行委派、缺口判断、收口决策 |
| researcher（可并行多个实例） | 子主题研究：检索→质量自判→补检→原文深读→清洗回传 |
| writer | 一次性成文，生成句级引用标记 |
| CitationAgent | 逐条校验引用的事实支持率 |
| memory extractor（后台） | 研究完成后异步提取长期记忆 |

## 4. 用户交互流程

### 4.1 主流程：发起研究到获得报告

1. 用户登录（JWT），进入会话页，可开启/关闭 HITL 开关。
2. 输入研究问题，发起研究。
3. 系统意图路由：
   - 简单问题 → 直接流式回答，结束；
   - 复杂问题信息不足 → 澄清对话（最多 2 轮）；
   - 信息充足 → 生成 research brief 与研究计划。
4. （HITL 开启时）展示计划卡片，用户批准/修改/取消。
5. 进入研究阶段，前端实时流式展示：各子智能体的步骤、正在检索的查询词、发现的来源、思考过程；来源按 web/知识库分类展示。
6. （HITL）用户可随时：中断运行、追加提示改变研究方向。
7. 研究收口，writer 一次性成文，正文流式渲染（Markdown/公式/代码块/句级引用角标）。
8. CitationAgent 校验引用，报告定稿。
9. 用户导出 MD 或 PDF；可回滚到历史快照、查看记忆、管理会话。

### 4.2 中断与恢复流程

1. **主动中断**：用户点击停止 → 取消幂等返回 → 前端进入停止态，提供「补充条件继续」「换个主题」入口。
2. **断线恢复**：连接异常断开 → 前端指数退避重连（1s 起 ×2，上限 30s，≤5 次）→ 重连后按最后收到的事件序号重放缺口 → 继续跟随实时流。研究在后台继续执行，不受连接断开影响。
3. **服务重启恢复**：重启后扫描中断任务并标记，用户可从检查点续研。
4. **HITL 恢复**：重连后若处于等待人工输入状态，重建对应交互卡片。

### 4.3 知识库流程

1. 用户进入知识库页，拖拽上传文档（单文件 ≤50MB，单次 ≤20 个）。
2. 系统校验扩展名白名单与文件头魔数 → 原件存对象存储 → 解析切块 → 进入异步向量化管道。
3. 前端轮询向量化状态（存在待处理切片时每 3s，全部完成即停）；失败切片可重试。
4. 已索引文档在研究中被本地检索路引用，引用角标可定位到具体切片。
5. 支持文档搜索、统计查看、单个/批量删除（元数据、对象存储、向量索引三处一致清理）。

## 5. 功能模块需求

### M1 意图路由与澄清

- 入口意图分类：直接回答 / 深度研究；结构化输出。
- 直接回答路径：单次生成、流式输出、秒级响应。
- 澄清：判断信息充分性，生成澄清问题；上限 2 轮，达标或信息足够后进入计划。

### M2 计划与批准

- 将研究目标压缩为 research brief：研究目标、范围、关键子问题、排除项。
- 生成研究计划（大纲、子主题、检索策略、预算），HITL 开启时交用户批准后执行。

### M3 研究编排（supervisor）

- 按 brief 拆分子主题，动态派发并行 researcher（默认 3–5，上限可配）。
- 汇总子智能体回传，判断知识缺口：缺口未闭合且预算未尽 → 派发补充研究；否则收口进入写作。
- 全部决策落检查点，可回溯。

### M4 研究执行（researcher 子智能体）

- 工具集：`web_search`、`kb_search`、`fetch_url`（原文深读）；工具集可经 MCP 扩展。
- 内部行为：检索 → 检索质量自判（不足则换查询词补检）→ 可疑证据读原文核实 → 清洗压缩，回传「结论 + 证据 + 来源清单」。
- 工具：Web 检索多 provider 链式降级（顺序可配、单查询超时、限流与结果缓存、全链失败降级空结果+告警）。

### M5 本地知识库检索

- 混合检索：向量多路召回 + 全文检索双路并行 → RRF(k=60) 融合 → cross-encoder 重排 → Parent-Child 上下文扩展（父 2048 / 子 512 字符）。
- 查询多变体/分解提升召回。
- 降级：重排模型失败降级 LLM 重排；全文检索不可用降级 BM25。

### M6 证据与引用（反幻觉体系）

- **稳定 source_id**：所有证据在产生时编址，跨轮次唯一，全链路可溯源。
- **可信度分层**：官方原文/一手数据 > 权威机构报告 > 权威媒体 > 普通转载 > 来源不明（排除）；评分 = 来源先验 + LLM 内容判断融合。
- **引用三段式**：证据携带稳定 source_id → writer 生成句级内联标记 → CitationAgent 逐条校验事实支持率（supported / partially_supported / unsupported 三档）；unsupported 句子必须改写、补证或删除。
- 报告引用区与正文角标同源生成；悬挂引用自动剔除。

### M7 报告生成与导出

- writer 输入 brief + 全部研究结论，一次性成文。
- 导出 MD（不阻断）；导出 PDF 先过质量门禁：error 级阻断并返回问题清单，warning 级放行并携带告警；PDF 渲染后回读校验。
- 质量门禁规则：空报告、引用段缺失/为空、正文低于最小长度、单一来源引用占比超阈、引用事实支持率低于阈值。

### M8 长期记忆

- 热路径只读：研究开始时按用户检索相关记忆注入 brief（条数可配，按用户 namespace 隔离）。
- 写入全部走后台：研究完成后异步提取。
- 用户可查看自己的记忆清单；记忆功能可整体开关。

### M9 流式事件与断线续流

- SSE 传输，事件语义对齐 AG-UI 标准：RUN_STARTED / RUN_FINISHED / RUN_ERROR、TEXT_MESSAGE_START/CONTENT/END、TOOL_CALL_START/ARGS/END、STATE_SNAPSHOT/STATE_DELTA、STEP_STARTED/FINISHED，及 HITL 中断扩展事件。
- **事件日志架构**：所有事件带单调递增序号写入持久事件日志（按 run_id 分区、设保留期）；SSE 连接是事件日志的可丢弃视图；运行任务与连接解耦。
- 断线续流：客户端凭最后事件序号（或 Last-Event-ID）请求 `?after=<seq>`，先重放缺口再继续实时跟随；重放按序号幂等去重。
- 心跳保活：超过可配间隔（默认 15s）无事件则发注释帧。
- 协议不变式：流必以终态事件结束；未知事件类型客户端静默忽略。

### M10 会话管理与恢复

- 会话列表、搜索、新建、重命名、置顶、删除（乐观更新失败回滚）。
- 历史消息查看；历史检查点快照列表与时间旅行回滚。
- 同一会话同时只允许一个运行中任务（冲突 409）；取消幂等。
- 会话消息超阈值时自动摘要压缩（保留最近若干条原文）。
- 会话归属守卫：非本人资源一律 404。

### M11 知识库文档管道

- 上传：multipart，大小/数量限制，扩展名白名单 + 文件头魔数校验，原件存对象存储。
- **事务性发件箱**：文档元数据 + 切片 + 发件箱消息单事务落库；消息发布成功才标记已发；消费端启动时补偿扫描未发消息。
- 消费：幂等消费（已索引跳过）→ 写向量索引 → 回写状态 → 确认；按消息体重试计数，超限进死信队列。
- 降级：消息发布失败时降级同步向量化，不阻断上传。
- 管理：列表（关键词搜索/统计）、向量化状态、失败重试、单删/批删（三处存储一致清理）、支持的扩展名查询。

### M12 认证与管理

- JWT 登录签发（有效期可配）；当前用户查询；失败文案不区分「用户不存在/口令错误」。
- 身份只从令牌派生，接口不接受请求参数指定用户身份。
- 管理员：业务配置查看与热更新（区分热生效/需重启字段）；健康检查端点（无鉴权）。

### M13 前端

- 技术栈：Vue3 + Pinia + Naive UI + TypeScript + Vite + vitest。
- 页面：登录、研究会话、知识库管理；侧边栏会话历史。
- 研究会话页：统一事件 reducer 消费标准事件；子智能体实时步骤与来源流；正文流式渲染（Markdown/KaTeX/代码高亮/句级引用角标上标）；4 类交互元素（计划批准卡、澄清卡、停止/转向入口、导出门禁提示）。
- 来源按 web/知识库幂等去重；401 统一跳登录；断线自动重连与事件重放。

## 8. 非功能需求

### 8.1 性能与预算

- 直接回答秒级响应；SSE 首事件即时；研究阶段子主题级并行。
- 超时矩阵：LLM 单次 60s（重试 2 次）、单查询检索 15s、单轮研究看门狗 900s（run 与 resume 同防护）、PDF 渲染 30s——均可配。
- 预算上限：总研究轮次、并行子智能体数（默认 3–5）、单子智能体工具调用次数、证据条数（默认 40）与字符预算（默认 60000）。

### 8.2 可靠性与降级

- 一切降级必须记日志，禁止静默失败：检索全链失败降级空结果+告警；重排失败降级 LLM 重排；消息队列失败降级同步向量化；结构化输出失败节点级降级并留痕；Redis 不可用降级单进程取消。
- 幂等：取消、消息消费、事件重放、来源去重。
- 检查点：阶段边界与决策点持久化；服务重启后中断任务可标记、可续研。

### 8.3 可观测性

- 遵循 OpenTelemetry GenAI 语义约定：每次运行一个 root span，LLM/检索/工具/重试 child span；记录 token 用量、TTFT、成本；traceparent 跨消息队列传播；trace 落库前脱敏。
- 观测后端 Langfuse（自托管）。

### 8.4 安全

- 凭据一律环境变量注入；缺失凭据 fail-closed 或显式降级记日志。
- 间接注入防护：检索语料与网页读回内容视为不可信输入，指令/数据分离、内容包装隔离。
- 导出前输出消毒（防 XSS/下游注入）；工具最小权限；fetch_url 出站白名单、禁内网网段、响应大小/类型上限（SSRF 防护）。
- 上传文件魔数校验；会话归属 404 守卫；鉴权失败防账号枚举。

## 9. 质量与评测要求

- **离线门禁**：golden set（50–200 真实 case）纳入 CI；指标含检索 recall@k / nDCG@10、RAGAS faithfulness / context precision、引用事实支持率；凡修改 prompt/模型/检索管线必跑阈值断言。
- **线上抽样**：1–5% 流量跑 LLM-as-judge（judge 须先与人工标注校准）；失败 case 回流扩充 golden set。
- **确定性检查**：schema 合法性、PII、成本/延迟预算对每次输出执行。
- **契约测试**：前后端事件协议自动化对拍，防止漂移。

## 10. 验收标准

- **功能**：§4 全部用户交互流程逐条可验证（发起研究→计划批准→并行研究→中断/转向→断线恢复→导出）。
- **质量**：golden set 各指标阈值达标；端到端报告人工抽检通过。
- **工程**：断线重放零事件丢失；重启后中断任务可标记可恢复；取消幂等；trace 全链路可查；后端单测 + 契约测试 + 前端组件测试全绿。

## 11. 范围外

- 端到端强化学习训练自研模型。
- 全语料知识图谱索引（GraphRAG 类）。
- 多租户计费、开放 API 平台化。
