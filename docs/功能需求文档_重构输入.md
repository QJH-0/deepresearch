# DeepResearch 功能需求文档（重构输入）

> **用途**：作为在新目录重新开发的唯一需求依据。本文档只描述「做什么」与业务规则，不描述现有代码实现。
> **来源**：2026-09-26 对现有系统全量调研（后端路由/服务/基础设施、多智能体图、前端、测试与部署）提炼。
> **技术栈约束**：保留现有技术栈，仅做版本整理升级（见 §9）。

---

## 1. 产品定位

多智能体深度研报系统。用户提出研究问题后，系统通过 LangGraph 编排的 10 节点智能体工作流，结合 Web 联网检索与本地向量知识库双路检索，经证据评审、反思补搜的闭环迭代，产出带引用溯源的结构化研究报告，支持流式推送、人工介入（HITL）、中断恢复与导出。

**用户角色**：普通用户（研究、知识库管理）、管理员（运行时配置热更）。

---

## 2. 核心用户路径

1. **登录** → JWT 鉴权，失败文案不区分「用户不存在」与「口令错误」。
2. **发起研究** → SSE 流式观察执行过程（节点状态、思考流、正文流、来源）→ 获得带引用的报告 → 导出 PDF/MD。
3. **HITL 介入** → 在澄清、计划审批、证据缺口、报告评审节点收到中断卡片 → 提交答复后续研。
4. **中断与恢复** → 主动取消 / 断线 / 服务重启后，从检查点续研或回滚到历史快照。
5. **知识库管理** → 上传文档 → 异步向量化 → 在研究中被本地检索引用；支持状态查询、失败重试、删除。
6. **会话管理** → 历史会话列表、搜索、重命名、置顶、删除、查看历史消息。

---

## 3. 功能性需求

### F1 意图路由与澄清

- 入口节点对用户输入做意图分类：**直接回答**（简单问答，秒级响应）或 **multiagent 深度研究**。
- 直接回答路径：单次 LLM 生成，流式输出，直接结束。
- 澄清路径：LLM 判断是否信息不足，生成澄清问题；**澄清上限 2 轮**，防止死循环，达到上限或信息足够后直通研究计划。
- 意图路由与澄清均为结构化输出节点（schema 约束，非提示词约定）。

### F2 研究工作流（10 节点图）

**拓扑**：`intent → (direct_answer | clarify → plan) → (web_search ∥ local_rag) → retrieve_grader → deep_dive → analyze → write`

10 个节点与智能体角色一一对应：

| 节点 | 角色 | 职责 | 结构化 |
| --- | --- | --- | --- |
| intent | intent_router | 意图分类 | 是 |
| direct_answer | direct_responder | 简单问答正文 | 否 |
| clarify | clarifier | 澄清问题生成 | 是 |
| plan | planner | 研究计划：大纲、子问题、检索计划、预算 | 是 |
| web_search | scout_web | Web 检索执行 + 结果整理 | 是 |
| local_rag | scout_local | 本地知识库检索 + 结果整理 | 是 |
| retrieve_grader | retrieval_grader | 检索充分性裁判（内层循环） | 是 |
| deep_dive | evidence_judge | 证据可信度评分、审计标记、可疑证据读原文（唯一带工具 fetch_url 的节点） | 是 |
| analyze | analyst | 结论 + 缺口 + 补检词一次产出（外层循环决策） | 是 |
| write | writer | 成文 + 引用校验修复 | 否 |

**两级循环（业务规则，层级不可混用）**：

- **内层重检**：`retrieve_grader` 判定检索不充分且未达 `max_retrieval_rounds`（默认 2）时，带着新的检索词扇回 web_search 与 local_rag 两条边重检；充分或达上限则放行。
- **外层续研**：`analyze` 产出 `next_action`（reflect/write）；为 reflect 且未达 `max_iterations`（默认 3）时回到检索阶段继续研究，否则进入 write。
- 判定逻辑收在节点内，条件边只读结果字段，不做判断。
- **recursion_limit** 必须按循环上限推算（默认 25 会撞顶），公式：`10 + max_iterations × ((max_retrieval_rounds+1)×3 + 3)`。

**结构化输出规则**：

- 7 个结构化节点走 `create_agent(response_format=...)`；无工具节点用 `ProviderStrategy(schema, strict=True)`（**必须显式传**——自动策略白名单不认 qwen，裸 schema 会退化为工具调用策略）；带工具节点（deep_dive）必须用 `ToolStrategy`（原生 json_schema 与 tool_calls 不兼容）。
- 结构化节点的提示词**不得规定输出格式**（格式由 schema 承担）。
- 结构化失败抛统一异常，**是否降级由各节点自行判断并留痕**，不静默。
- 结构化节点的型号必须支持 json_schema（白名单校验），不支持则**启动即失败**（有意设计）。

### F3 双路并行混合检索

**Web 检索路**：

- Provider 链式降级，顺序可配（`search_providers`）：ddgs（含 1.5s 限流间隔 + Redis 1h 结果缓存）→ ddgs MCP（uvx 子进程）→ tavily → searxng。
- 单查询整链超时 `search_timeout_seconds`（默认 15s）；全部失败降级为空结果 + 告警，不阻断流程。

**本地 RAG 路**：

- 查询重写多变体 → Milvus 向量多路召回 + PostgreSQL 全文检索（`content_tsv` 生成列；PG 全文不可用时降级 BM25）→ **RRF 融合**（k=60）→ **重排**（DashScope `gte-rerank-v2`，失败降级 LLM 重排）→ **Parent-Child 上下文扩展**（父块 2048 字符 / 子块 512 字符）。
- 两路检索**并行扇出**，共同汇入 retrieve_grader。

**证据累积规则**：`web_evidence`、`local_evidence`、`research_notes` 等为 operator.add 累积型字段，节点只回增量；**无新证据时不得回写旧值**（否则「旧值+旧值」证据翻倍）。

### F4 证据裁判与引用溯源（反幻觉体系）

- **source_id 编址**：前缀必须按 `_retrieval_pass_index()` 生成 = `外层轮次 × (内层上限+1) + 内层轮次 + 1`，形如 `WEB{idx}_{queryIndex}` / `LOC{idx}`。**禁止用 iteration 作批次号**——内层重检会让同一外层轮次内多次检索撞 ID，引用溯源断链（历史实测证据重复率 41%）。
- **证据评分**：来源信誉先验（`evidence_prior_weight` 默认 0.4）+ LLM 融合评分（可开关 `evidence_llm_fusion`）。
- **deep_dive 证据裁判**：可信度评分、审计标记、重建 evidence_pool；对可疑证据可通过 fetch_url 读原文核实。
- **引用收口**：write 节点仅从 `source_index` 合法 ID 集生成引用角标，非法/悬挂引用自动剔除。
- **证据预算**：`context_evidence_limit`（默认 40 条）+ `context_evidence_budget_chars`（默认 60000 字符），超出实测裁剪。

### F5 长期记忆（langmem 双通道）

- **热路径**：研究开始时按用户检索注入相关记忆到 plan 上下文（namespace 按用户隔离，`memory_hot_path_top_k` 默认 5）。
- **后台通道**：研究完成后异步提取记忆写回（`memory_background_enabled`）。
- 可通过开关 `enable_memory` 整体关闭；提供 `GET /research/memories` 查看。

### F6 会话持久化、取消与恢复

- **Checkpointer**：LangGraph `AsyncPostgresSaver` 落 PostgreSQL，降级链 **Postgres → Redis → 内存**（受 `checkpointer_backend` 控制）。
- **取消**：`POST /research/cancel` 幂等（200/202）；本进程取消 + **Redis Pub/Sub 跨实例广播**（频道 `task:cancel`）；Redis 不可用时降级单进程取消。
- **并发约束**：同一 thread 同时只允许一个运行中任务，冲突返回 409。
- **孤儿任务恢复**：服务重启后扫描「Redis 取消拘留标记 + PG checkpoint」双条件，将中断任务标记为 `interrupted_by_restart`（标记 TTL 7 天）。
- **续研**：`POST /research/resume`，三种 mode——`continue`（从检查点继续）、`answer`（回答 HITL 中断，按 interrupt kind 校验，不匹配 422）、`modify`（带修改意见续研）。
- **历史与回滚**：`GET /research/history/{id}` 快照列表；`POST /research/rollback` 时间旅行回滚到历史检查点。
- **运行看门狗**：单轮研究 `run_timeout_seconds`（默认 900s）超时强制收尾，记录 `last_node`；run 与 resume 两条路径都必须有超时保护。
- **摘要压缩**：会话消息数超过阈值（默认 20）时 LLM 压缩历史，保留最近 6 条原文，摘要消息 id 固定。
- 后台任务：研究完成后异步生成会话标题（LLM）。

### F7 SSE 流式协议（10 种事件）

信封格式 `{type, ts, data}`，`data: {json}\n\n` 帧；出口经 Pydantic 校验。

| 事件 | 关键字段 | 语义 |
| --- | --- | --- |
| run.started | thread_id, run_id | 运行开始 |
| agent.status | node, label, phase, detail? | 节点状态推进 |
| message.start | message_id, role?, node? | 消息气泡开始 |
| message.delta | message_id, text | 正文增量 |
| message.thinking | message_id, text | 思考流增量（仅 thinking_nodes 配置的节点） |
| sources.found | sources[]（url/title/snippet/source_type=web\|kb/chunk_id） | 来源发现 |
| interrupt.raised | interrupt_id, kind, payload | HITL 中断 |
| run.completed | message_id, final_state, final? | 正常完成 |
| run.cancelled | reason | 已取消 |
| run.error | code, message | 错误终态 |

**协议不变式**：流必须以 completed / cancelled / error 三者之一结束；未知事件类型前端静默忽略（向后兼容）。

**心跳**：超过 `sse_heartbeat_seconds`（默认 15s）无事件产出时发 `: ping\n\n` 注释帧保活。

**断线续流（前端职责）**：非用户主动中止的连接失败 → 指数退避重连（1s 起 ×2，上限 30s，最多 5 次）→ 拉取 `GET /threads/{id}/state` 判断（awaiting_input 则重建 HITL 卡片后停；不可续则消息对齐后停）→ 全量拉取历史消息对齐 → `POST /research/resume {mode:'continue'}` 续流。用户取消或切换会话即中止重连。

### F8 HITL 人工介入

4 种中断 kind（`interrupt.raised` 的 payload）：

| kind | 触发点 | 默认开关 |
| --- | --- | --- |
| clarification | 澄清节点 | 由 clarify 流程内在驱动 |
| plan_approval | 计划审批 | hitl_config.plan_review = true |
| evidence_gap | analyze 发现证据缺口 | hitl_config.analyze_clarify = true |
| report_review | 报告评审 | hitl_config.write_review = false |

- `hitl_enabled` 全局开关 + `hitl_config` 分项开关；`clarify_max_rounds` 默认 2。
- 中断状态可经 `GET /threads/{id}/interrupt` 重建（断线恢复场景）。
- 前端提供 4 类交互卡片：计划审批、澄清回答、证据缺口确认、报告评审。

### F9 知识库文档管道

- **上传**：multipart，单文件 ≤50MB，单次 ≤20 个；扩展名白名单 + **文件头魔数校验**防伪装；原始文件存 MinIO。
- **事务性发件箱（最终一致性）**：PG 单事务写入文档元数据 + 切片 + outbox 消息（pending）→ 发布 RabbitMQ 成功后才标记已发送（显式检查返回值，防静默失败）→ 消费者处理；**消费者启动时补偿扫描 pending outbox 重发**。
- **消费**：topic exchange `chunk-sync` + DLX/DLQ；幂等消费（已 indexed 跳过）→ 写 Milvus/BM25 → 回写 PG 状态 → 手动 ACK；按消息体 hash 计数重试，超过 `chunk_retry_limit`（默认 3）nack 进 DLQ。
- **降级**：MQ 发布失败时降级为同步向量化，不阻断上传。
- **管理**：列表（关键词搜索、带统计）、统计、单删/批删（PG + MinIO + 向量三处清理）、按文档查询向量化状态、失败切片重试、支持的扩展名查询。

### F10 报告导出与质量门禁

- **MD 导出**：`GET /research/threads/{id}/export/md`，不阻断（内容逃生通道）。
- **PDF 导出**：`GET /research/export/pdf`，先过质量门禁，error 级阻断（422 + issues 清单），warning 级放行并在 `X-Report-Warnings` 头携带告警。
- **门禁规则（report_check）**：空报告、缺失/空引用段、正文 <800 字、单一来源引用占比 >60% 等。
- **PDF 生成**：Playwright Chromium 渲染 A4（30s 超时）+ 生成后 `verify_pdf` 回读校验。

### F11 认证、鉴权与管理

- JWT（HS256）登录签发，有效期可配（默认 720 分钟）；`GET /auth/me` 查询当前用户。
- **身份只从令牌派生**，接口不接受请求参数指定用户身份。
- 会话归属守卫：非本人的 thread 资源一律返回 404（不泄露存在性）。
- 管理员：`GET /admin/config`、`POST /admin/config/reload` 热更业务配置，返回已生效字段与需重启字段清单。
- **需重启字段**：模型主档、thinking_nodes、checkpointer_backend。
- 健康检查：`GET /health`、`GET /health/live`（无鉴权）。

### F12 前端功能

- **技术形态**：Vue3 + Pinia + Naive UI + TypeScript + Vite；markdown-it（含 KaTeX 公式、highlight.js、流式 MD 修补）。
- **页面**：登录页；研究会话页（发起研究含 HITL 开关、流式过程卡片 + 节点时间线、思考日志、来源列表、停止/续研双显式入口「补充条件继续」「换个主题」、历史回滚菜单、导出 PDF/MD 含门禁提示）；知识库页（上传进度、任务列表、向量化状态轮询——有 pending 切片每 3s 轮询、全 indexed 停止，搜索/重试/删除）；侧边栏会话历史（搜索/新建/重命名/置顶/删除）。
- **统一事件 reducer**：run 与 resume 共用事件消费链；10 种事件分发；多气泡合并（后续节点的 message_id 映射到首个主气泡）；来源按 `web:url` / `kb:chunk_id` 幂等去重；悬挂引用剔除；[source_id] 角标上标渲染。
- **事件契约对拍**：前端事件类型定义从后端契约文件生成/对齐，有自动化测试防止漂移。
- 401 统一兜底跳登录；会话列表事件驱动刷新（非轮询）；重命名/置顶/删除乐观更新失败回滚。

## 4. 数据需求（实体与语义）

| 实体 | 存储 | 关键语义 |
| --- | --- | --- |
| documents | PostgreSQL | 文档元数据、向量化状态（queued/indexed/failed） |
| document_chunks | PostgreSQL | 切片内容、`content_tsv` 生成列支撑全文检索、每切片同步状态 |
| chunk_sync_messages | PostgreSQL | 事务性发件箱（pending/sent），与文档写入同事务 |
| 向量索引 | Milvus | 切片向量（collection 可配，默认 mult_agent_memory） |
| 原始文件 | MinIO | 上传原件，bucket 可配 |
| chat_threads | PostgreSQL | 会话元数据：标题、置顶、归属用户 |
| checkpoints | PostgreSQL（LangGraph） | 图状态快照，支撑续研/回滚/重启恢复 |
| memories | PostgreSQL（langmem） | 用户级长期记忆，namespace 按用户隔离 |
| 运行时标记 | Redis | 运行中任务标记、取消广播频道、重启拘留标记（TTL 7 天）、检索结果缓存（1h） |

**数据一致性规则**：文档三处存储（PG/MinIO/Milvus）删除必须同步清理；发件箱保证向量化最终一致；检索派生数据与主数据的一致性由 outbox + 消费幂等 + 启动补偿三重保障。

## 6. 配置需求

- **双源配置**：中间件/密钥类走环境变量（LLM API key、PG DSN、Redis/RabbitMQ URL、Milvus、MinIO、JWT secret、用户表）；业务行为类走 `config.json` 支持热更（38 项，含模型分档、循环上限、HITL 开关、证据预算、超时矩阵）。
- **模型分档**：`node_models` 按 10 节点分别配 model/temperature，不硬编码；默认 `qwen3.8-max`；长文用 Max、判定用 Flash 的分档原则。
- **thinking_nodes** 默认空：兼容通道不透出 reasoning_content，开启只增加延迟与成本。
- **关键默认值**：max_iterations=3、max_retrieval_rounds=2、llm_timeout=60s、llm_max_retries=2、run_timeout=900s、search_timeout=15s、sse_heartbeat=15s、context_evidence_limit=40、context_evidence_budget_chars=60000、chunk_retry_limit=3、clarify_max_rounds=2、evidence_prior_weight=0.4。

## 7. 非功能需求

- **超时矩阵**：LLM 单次 60s（重试 2 次）；单查询检索 15s；单轮研究看门狗 900s（run 与 resume 同覆盖）；PDF 渲染 30s。
- **降级规则**：Redis 断→单进程取消；PG 断→checkpointer 降级 Redis/内存；rerank 模型失败→LLM 重排；PG 全文不可用→BM25；搜索全链失败→空结果+告警；MQ 失败→同步向量化；结构化输出失败→节点级降级并留痕。**所有降级必须记日志，禁止静默**。
- **幂等**：取消接口幂等；消息消费幂等；前端来源去重幂等；interrupt 重建幂等。
- **响应性**：直接回答路径秒级响应；SSE 首事件即时；15s 心跳保活。
- **安全**：凭据只走环境变量；文件上传魔数校验；fetch_url 需 SSRF 防护；会话归属 404 守卫；鉴权失败文案防账号枚举。
- **可观测**：运行超时记录 last_node；搜索降级告警；结构化失败留痕。

## 10. 已知缺陷清单（新实现必须修正/避免）

1. 文档重试成功路径存在未定义变量引用（NameError），重试必失败——新实现需覆盖该路径测试。
2. run 路径有看门狗、resume 路径无超时保护——两条路径必须同防护。
3. 存在同功能双路由（两套 state 查询端点）——新设计一功能一端点。
4. 配置读取未收口（多处 getattr 兜底、白名单双处定义、RAG 初始化三处重复）——配置单一维护源。
5. 前端知识库页绕过 store 自持状态、HITL 重建用裸 fetch 无鉴权头、节点标签硬编码镜像后端——状态管理单一真相、接口层统一鉴权、标签由事件负载携带。
6. 同步 MQ 客户端（BlockingConnection）与 asyncio 主进程混用——异步化或隔离到后台线程。
7. 服务初始化存在懒加载与生命周期双路径——统一 lifespan 初始化。
