> 上游分析：`docs/plans/优化计划-多智能体架构升级.md`（架构体检 + 行业基准 + A/B/C 三档建议）

> 制定日期：2026-09-18。基线：后端 536 passed / 2 skipped，回归专项 116 passed / 7 deselected。

## 1. 目标（Goal）

**把"一个节点 = 一次 LLM 调用"的流水线，升级为"控制流 + 智能层 + 上下文层"三层齐备的 Agentic RAG 系统**，同时不破坏现有的三处图语义资产（并行 fan-out/fan-in、双终止条件反思回环、检查点续研 + HITL）。

完成标准：

1. State 语义自洽——reducer 与节点返回约定一致，无重复累加、无死字段
2. 检索从"固定一轮 × top-4"变为"grader 驱动的自适应 1–3 轮"
3. 证据不再全量注入，按上下文预算分层取用
4. 节点数从 10 降到 8，且每个节点都有明确的信息增量
5. 全部现有测试通过 + 新增语义断言（注入漂移可验证其有效性）

验证方式：`pytest` 三条基线命令全绿 + 新增 reducer 语义测试 + 一次人为漂移验证。

## 2. 阻塞问题（2 个）

### 阻塞问题 1：本次开发范围

| 选项 | 内容 | 影响 |
| --- | --- | --- |
| **A（推荐先做）** | 只做地基与上下文层：修 reducer、清死字段、证据分层 + compaction + note-taking + token 预算 | 不改拓扑、不动 schema 绑定，风险低、可独立验收 |
| A + B | 再做智能层：`retrieve` 子图 + grader + rewrite、`deep_dive` 加 `fetch_url`、`reflect` 并入 `analyze` | 节点 10→8，需同步改 3 个测试文件，工作量约为 A 的 2–3 倍 |

**默认建议**：先做 A 并验收，再开 B。理由：B 的 grader 依赖 A 建立的证据分层（否则 grader 输入仍是膨胀的重复证据，评估会失真）。

### 阻塞问题 2：State 字段语义变更对已持久化检查点的影响

**现状**：State 经 `AsyncPostgresSaver` 持久化（`runtime.py:63-109`），支持"取消/重启后断点续研"。

**风险**：删除字段（如 `code`）或改变 reducer 语义后，**升级前已存在的 thread 检查点**在续研时可能表现异常——不是崩溃，而是拿到旧的膨胀数据（`web_evidence` 已被重复累加过）。

**默认建议**：不做迁移代码，改为**升级时清理开发环境的 checkpoint 表**，并在发布说明中标注"升级前未完成的研报需重新发起"。理由：
- 死字段无读取方，缺失不影响运行
- 重复累加是既成事实，无法从已持久化的数据里还原原始证据条数
- 生产若已有在跑任务，让它们跑完再升级，比写迁移逻辑更省

**待确认**：当前是否有正在运行/待续研的真实 thread（若有，需先跑完）。

## 4. 计划（Plan）

### 阶段 A1：修正 State reducer 语义（P0，地基）

**问题**：`state.py` 15 个字段声明 `operator.add`，但节点的返回约定不统一，导致两类错误。

**实测证据**（llmdev 环境最小复现）：

```
输入 items=['seed']，节点 return {'items': existing + ['new']}  →  ['seed','seed','new']  ← 重复
对照：节点 return {'items': ['new']}                              →  ['seed','new']         ← 正确
```

**正确的字段语义分类**：

| 字段 | 现 reducer | 目标语义 | 修法 |
| --- | --- | --- | --- |
| `outline` | add | **覆盖**（当前计划） | 去 reducer |
| `sub_questions` | add | **覆盖** | 去 reducer |
| `research_questions` | add | **覆盖** | 去 reducer |
| `search_plan` | add | **覆盖** | 去 reducer |
| `supplementary_queries` | add | **覆盖**（当前补搜计划） | 去 reducer |
| `evidence_pool` | add | **覆盖**（每轮从 raw 重建） | 去 reducer |
| `source_index` | add | **覆盖** | 去 reducer |
| `audit_flags` | add | **覆盖** | 去 reducer |
| `findings` | add | **覆盖** | 去 reducer |
| `claim_map` | add | **覆盖** | 去 reducer |
| `missing_gaps` | add | **覆盖** | 去 reducer |
| `web_evidence` | add | **累积**（证据库） | 保留 reducer，节点只返回增量 |
| `local_evidence` | add | **累积** | 保留 reducer，节点只返回增量 |
| `web_search_trace` | add | **累积**（审计轨迹） | 保留 reducer，节点只返回增量 |
| `local_rag_trace` | add | **累积** | 保留 reducer，节点只返回增量 |
| `clarifications` | add | **累积**（多轮问答） | 保留（节点已只返回增量，无需改） |
| `chat_messages`/`agent_messages` | add_messages | 累积 | 保留 |

> 判据：**语义是"当前值"的字段用覆盖，语义是"历史累积"的字段用 add。**
> `evidence_pool`/`source_index`/`audit_flags` 每轮由 `deep_dive` 从全量 raw evidence 重建，属"当前值"；
> `findings`/`claim_map`/`missing_gaps` 每轮由 `analyze` 重新分析得出，同属"当前值"。

> ### ⚠️ 实施中的修正（2026-09-18，A1/A2 完成后回看）
>
> **A1 落地后，上下文膨胀的主因已被消除**——原本每轮迭代证据列表近似翻倍（`e(n+1) = 2·e(n) + new`），
> 现在只按增量累加。这让 A3 的**预算与裁剪机制（A3-1 / A3-2 / A3-4）价值显著下降**：
> 默认阈值收紧有静默降质风险（无 Golden Set 可验证），放松则几乎不触发。
>
> 反过来，**A3-3（note-taking）是 A3 里唯一的新增能力**：让结论跨轮通过 `research_notes` 传递，
> 替代下游重读全部证据。价值高于其余三项。
>
> **修正后的顺序**：
> 1. **A3-3 note-taking 优先**（新增能力，不依赖评估集）
> 2. A3-1 + A3-4 合并为「防病态膨胀的安全阀」——采用**高默认阈值**，只在证据量异常时才生效，
>    避免在无评估集的情况下影响正常路径质量
> 3. A3-2 compaction 与 A3-1 一并实现（本质是同一次选择 + 字段裁剪）
>
> 另：原计划写「State 加 `context_budget`」**不采纳**——预算属配置项，写入 State 会与
> `config.json` 形成第二个事实源，违反「单一维护源」。改为各节点从 config 读取。
